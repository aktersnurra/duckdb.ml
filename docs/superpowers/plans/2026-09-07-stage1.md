# Stage 1 compatibility and FFI Implementation Plan

> **For agentic workers:** Execute inline using the writing-plans and test-driven-development skills; the approved single-writer task forbids subagent dispatch. Check off only demonstrated results.

**Goal:** Reproducibly compile a project-local OxCaml toolchain, run both scheduler stacks and a minimal chunk/vector DuckDB query, and select an FFI from compiled comparative evidence.

**Architecture:** Private stage-1 probes, not public ownership APIs. Project-local opam root and switch isolate all dependency changes. A generated-stub probe and a handwritten-stub probe share query expectations; each retains native arguments before releasing the runtime lock.

**Tech Stack:** OxCaml 5.2.0+ox as currently recommended upstream; pinned OxCaml/default opam snapshots; Base, Dune, Async, Eio, Ctypes; DuckDB public C API on x86-64 glibc.

## Global constraints

- Use `jj`, never raw Git commands; no publication, sudo or shared configuration changes.
- Full OxCaml; no upstream-OCaml fallback or weakened runtime tests.
- `.mli` first, Base by default, named ADT errors and `result` for expected failures.
- No unsafe casts in a safe API; all probes provisional, no lifetime/zero-copy claims.
- Use Dune, not Makefile wrappers. Warnings-as-errors only for authored development code.
- Ignore native downloads, switches, build caches and raw logs under `.local/`, `.deps/`, `_opam/`, `_build/`.
- Stop at a demonstrated blocker; preserve exact command, output and reproducible checkpoint.

## Task 3: two FFI probes and minimal query

**Files:** `stage1/handwritten_probe.mli`, `stage1/handwritten_probe.ml`, `stage1/handwritten_stubs.c`, `stage1/generated_bindings.mli`, `stage1/generated_bindings.ml`, `stage1/generate_stubs.mli`, `stage1/generate_stubs.ml`, `stage1/ffi_tests.mli`, `stage1/ffi_tests.ml`, `stage1/dune`.

**Private OCaml interface (write `.mli` first):**

```ocaml
type error = Open_failed of string | Connect_failed | Query_failed of string
val query_int64 : string -> (int64 array, error) result
```

This is an owned-copy BIGINT-only experiment, not a public API. Unsupported schemas fail explicitly. Any additional schema failure uses a named `Unsupported_schema` variant before implementation.

- [ ] Write assertions for `SELECT i::BIGINT FROM range(3) t(i)` returning `[|0L; 1L; 2L|]`, invalid SQL producing `Query_failed`, repeated invalid/valid cycles, empty result, and unsupported column type. Run for red.
- [ ] Handwritten C copies SQL to native memory before entering a blocking section, opens/connects, calls `duckdb_query`, fetches using `duckdb_fetch_chunk`, `duckdb_data_chunk_get_vector`, `duckdb_vector_get_data` and validity APIs, copies values with lock held, destroys chunks/results on success and error, disconnects then closes. No movable heap access while unlocked.
- [ ] Ctypes-generated stubs use `Cstubs.write_c ~concurrency:Cstubs.unlocked` (validate installed signature), native-owned argument storage across unlocked calls, and the same public chunk/vector API. Inspect generated C for conversion-before-unlock and cleanup. Do not infer lock behavior from generator options alone.
- [ ] Add a native slow-call test with a concurrent OCaml systhread heartbeat for each approach; require heartbeat while native work is in flight. Add C/OCaml accessor experiment for `int64#` if supported and boxed reference equivalence at signed 64-bit boundaries. Compile failures are evidence of unsupported syntax/representation, not a reason to claim support.
- [ ] Run `stage1/run runtest`; run ASan/UBSan native diagnostics (Valgrind if present), exercising failed query cleanup repeatedly. Check DuckDB's public header destruction documentation for all failure paths.
- [ ] Commit `test: compare DuckDB generated and handwritten stubs`; `jj new`.
