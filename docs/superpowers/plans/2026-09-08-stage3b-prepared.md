## Design before implementation

Follow writing-plans/type-driven/OCaml/tiger-style guidance: explicit interfaces first, small modules, named errors, no unsafe casts. Follow TDD and systematic debugging: record a failing command before implementing each seam, investigate compiler/native diagnostics against the exact runtime rather than changing the toolchain.

- `Scalar`: compact witnesses for Bool, Int8/16/32/64, Float32/64, String, Blob, Date (native int32 days), timestamp seconds/milliseconds/microseconds/nanoseconds and UTC-instant microseconds. Nullable field/parameter witness is distinct. Date/timestamp values preserve raw DuckDB values, including documented infinity sentinels; no float time conversion. Float32 binding accepts only exactly representable binary32 values (NaN allowed, sign of zero preserved); explicit caller rounding uses a named conversion. Int8/16 use range-checked ints, wider integers use int32/int64. Unsupported logical IDs are errors, never engine-coerced.
- `Row`: explicit owned decoder built from typed fields and products, validated against the full dynamic result schema before fetching, including empty results. NULL in a required field is a contextual error, not a fake zero. Column access is typed and checks runtime schema and bounds.
- Existing lifecycle code moves intact into a private `Resource` module only to expose the necessary private admission/child-retention seam to `Query`; public `Duckdb` remains the entry point. A prepared child belongs to a connection or revocable transaction. Operations serialize through the existing connection gate. Results exclusively reserve the connection until close; manual transitions fail fast. Parent/transaction cleanup revokes and drains, then closes result before prepared before connection. No metadata mutex spans a user callback or native work.
- Abstract prepared and result owners are global/reusable with dynamic Closed/Busy/Live_children checks. Binding uses 1-based parameter indices, must match the known engine parameter type exactly, supports rebind, and survives successful executions. Reset explicitly clears all bindings. All parameters must be bound before execute. A live result prevents reset/reexecution/prepared close; its lease blocks other connection operations. Close is idempotent. Failed prepare/execute/fetch and exceptions unwind owned state.
- Abstract chunk exists only as a local argument during synchronous fold. No owner accessor or transition is exported. The connection operation remains admitted throughout the callback, so reentrant/concurrent alias close/reset/fetch returns Busy without deadlock. The stage-2 local record and deep no-escape effect barrier remain, inside the exact runtime's inner Sys.with_async_exns boundary. Fold consumes/closes the result on success, stop, error or exception.
- Native code is split into shared internal resource declarations, prepared lifecycle stubs and typed vector/binding stubs. Stable native shells own SQL, binds, prepared/result/chunk resources before runtime release. Native references protect finalizer ordering. Pending actions run after every reacquisition. Borrowed numeric/validity reads use actual DuckDB vector buffers, including native int64#; strings/blobs and row decoding return owned copies.
